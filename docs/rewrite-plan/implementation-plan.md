# Vibe Town regional city builder — implementation plan

**Goal** — Rewrite Vibe Town as a browser city builder where regional growth depends on roads, housing, jobs, trade, utilities and public services. Use Cities: Skylines II as the reference for the breadth of player decisions and preserve Vibe Town’s own coastal art direction and interface.

**Architecture** — Put the authoritative simulation in a TypeScript Web Worker. Feed a Three.js viewport and React panels through separate, versioned read models. Build the rewrite on `rewrite/regional-city`, starting from `main` at or after `d540699`, with a playable scenario and measurable exit criteria at each milestone.

**Stack** — TypeScript 7, Vite, pnpm, Oxlint, Oxfmt, Three.js, React, IndexedDB, Node’s test runner and development-only Playwright. Blender can produce original glTF building kits once the rendering budget is established.

## 2. Rewrite boundary and dependencies

Replace the 38×38 authoritative tile grid, road-frontage rules, monthly aggregate economy, whole-scene rebuilds, DOM entry point and v1 save schema. Use the current Juniper Bay district, camera behavior, procedural models and save-protection tests as reference fixtures. Reuse visual geometry and math where they fit the new representation. Start development on the dedicated branch. Integrate reviewed milestones into that branch in order, then switch the main game entry point when the first regional release passes its acceptance gates.

| Dependency        | Decision and reason                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Three.js          | **Adopt behind a viewport boundary.** Share meshes and materials across buildings, instance repetitive props, load Blender assets as glTF, and use built-in camera and lighting infrastructure. Road mesh generation, terrain streaming, simulation and asset budgets remain project responsibilities. Start with `WebGLRenderer` and measure `WebGPURenderer` on the same fixture before adding another backend. [Three.js reference](https://threejs.org/docs/) · [Renderer comparison](https://threejs.org/manual/pages/webgpurenderer) |
| React             | **Adopt for the DOM.** The number of inspectors, tables, forms, overlays and keyboard states warrants components. Consume cached read models through an external store, with selected-entity queries on demand. The worker owns city data. Imperative Three.js code owns the frame loop. [React external stores](https://react.dev/reference/react/useSyncExternalStore)                                                                                                                                                                   |
| React Three Fiber | **Defer.** The core task is applying large batches of terrain, road and vehicle changes. Use explicit resource lifetimes and instance updates in Three.js. Reconsider R3F for a small standalone asset preview if React-driven scene composition proves useful there. [R3F performance guidance](https://r3f.docs.pmnd.rs/advanced/pitfalls)                                                                                                                                                                                               |
| Other libraries   | Add Playwright for browser regression tests. Consider a spatial index or polygon clipping library when road and parcel fixtures show a measurable need. Start with native browser storage, SVG charts, a small command protocol and typed arrays. Choose additional dependencies against a concrete correctness or performance benchmark.                                                                                                                                                                                                  |

## 3. Proposed module boundaries

| Path                                   | Owns                                                                                                                                                                                                                                  |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/core/world/`                      | Stable IDs, metre coordinates, seeded terrain, chunk boundaries, ownership and external connections. Buyable regions, render chunks and parcels have independent lifecycles.                                                          |
| `src/core/network/`                    | Road nodes, directed segments and turn connectivity. Road geometry supplies grade and frontage. Derived graphs supply walking, vehicle, transit and utility links.                                                                    |
| `src/core/sim/`                        | Fixed-step scheduler, households, firms, trip plans, goods, ledger, services and progression. Every system runs headless from a seed and ordered commands.                                                                            |
| `src/worker/`                          | Command sequencing, authoritative validation, simulation clock, typed viewport deltas, panel snapshots and query replies. Each accepted or rejected command returns its ID and world revision.                                        |
| `src/view/`                            | Three.js resource ownership, chunk culling and level of detail, glTF instances, camera, overlays, picking and construction previews. Render interpolation reads published positions between ticks.                                    |
| `src/ui/`                              | React HUD, tool dock, inspector, layers, alerts, history panels and accessibility. Subscribe at a low rate for summaries and refresh immediately after accepted edits.                                                                |
| `src/storage/`                         | IndexedDB checkpoints and save export/import. Use a new schema and storage namespace. Keep old saves available through the legacy version or export, with no migration work in the rewrite. Validate before swapping the active slot. |
| `tests/scenarios/` and `bench/region/` | Reference city seeds, command logs, expected economic and routing outcomes, browser walkthroughs and dense regional workloads.                                                                                                        |

## 4. Milestones in dependency order

Each milestone ends with a playable build or repeatable fixture. For changes spanning multiple systems, split PRs around a single scenario and preserve the earlier fixtures.

### A. Prove the architecture on a regional map

- [ ] Establish a deterministic worker loop and replay, then draw a terrain chunk, road and repeated building kit from view snapshots. Build the React inspector against published selection data.
- [ ] Run a regional benchmark with a seeded **8 × 8 km candidate map**, a **2 × 2 km starter area**, terrain with height and water, 10,000 rendered building instances, and 2,000 moving vehicle instances. Keep the full region navigable and load detailed geometry near the camera. Measure the renderer with both overview and low-angle camera routes.
- [ ] Verify a local road edit updates affected chunks, a paused scene uploads no recurring geometry, and a save interrupted mid-write leaves the previous checkpoint readable. Record cold load, memory, frame intervals, GPU upload bytes and command acknowledgement/visible-update latency. Set the supported map density and device tier from these results.

### B. Build roads and grow the first neighborhood

- [ ] Support straight and curved roads, automatic junction splitting, snap and grade previews, road upgrades, sidewalks and bridges. Validate each construction gesture as one command with a cost and explicit rejections. Keep lane and frontage updates in the same transaction as road topology.
- [ ] Generate buildable parcels along road frontage and allow zoning by strip or brush. Deliver low and medium density housing, shops, industrial lots and a simple external highway connection. Add original facades, roof variations and landscaping from the existing palette and an initial Blender kit.
- [ ] **Exit scenario** — Build a curved neighborhood across uneven terrain, zone both sides, connect power and water, grow a block, upgrade its road and reload without parcel duplication or displaced addresses. Hovering and demolishing target the same visible object at planning and low angles.

### C. Make traffic and the economy affect each other

- [ ] Add households with worker counts, income and housing budgets, and firms with staffing needs, cash and inventory. Define zone demand from actual vacancies, job access, affordability and goods sales. Use integer currency and explicit sources and sinks.
- [ ] Use deterministic routes with edge travel times, capacity, queues and route invalidation after edits. Distinguish reachability from arrival. Commute delays affect staffing, and deliveries transfer inventory only on arrival. Reserve shipment stock once and release or return it on cancellation.
- [ ] **Exit scenario** — Follow a manufacturer’s shipment to a shop and a household purchase. Cut the only connecting road. Commutes and delivery sales fall, inventory backs up or runs out, and the inspector identifies why. Reconnect via a slower route and verify measured recovery and ledger totals. Replay through a save boundary with the same outcomes.

### D. Make a growing city manageable

- [ ] Separate power, potable water and sewage. Add garbage collection, healthcare, fire response and education with building capacity, operating budgets and network-based coverage. Start with one dispatch-and-return flow shared by vehicle-based services.
- [ ] Add land purchase, districts and per-district tax or service policies. Implement land value, noise and pollution as visible spatial fields with clear inputs. Add bus stops, routes, capacity and waiting time using the existing trip planner. Introduce the problems through progression and make major systems available in sandbox.
- [ ] **Exit scenario** — Expand across a river onto purchasable land. Open the utility overlay to diagnose a shortage, add capacity, then replace some car trips with a bus service. Measure queue lengths, operating costs and district outcomes before and after.

### E. Deliver the regional game and broaden toward parity

- [ ] Release with a second map seed and a second opening strategy. Add medium and high density variety, mixed use, offices, freight terminals, passenger rail or tram, and connected external trade once the traffic and ledger gates hold. Stress-test infrastructure costs and bankruptcy recovery across several growth strategies.
- [ ] Map subsequent releases to capability families. Extend household lifecycles and schooling, add additional transit modes, train/port interchange, terraform tools, and seasonal effects when they affect placement, travel or service demand. Treat photo mode, audio, an asset editor and mod support as explicit product milestones with their own acceptance tests. DLC coverage and 1:1 content catalogs are separate scope decisions. [Official feature index](https://www.paradoxinteractive.com/games/cities-skylines-ii/features)
- [ ] **Release gate** — Complete a new-town playthrough from the starter area to regional expansion. Require automated regressions for the first ten in-game years, storage reload, a failed load that preserves existing data, input at different camera angles, and functional checks on accelerated Chrome, Firefox and Safari.

## 5. Scale and balance gates

- **First playable target** — 5,000 modeled residents, 1,000 buildings, a 10-year replay and all B/C scenarios. **Regional target** — 50,000 residents and 10,000 buildings after measurement. Represent demographic state by households or cohorts. Render a bounded sample of actual trips while preserving full route demand in counters.
- **Initial desktop budget** — Measure at 1080p on the Apple M4 used for the earlier review and a second integrated-GPU machine. Aim for p95 frame intervals under 25 ms during orbit, p95 construction input-to-visible change under 100 ms, and no growing worker backlog during five minutes at maximum speed. These are proposed targets. Record actual throughput, scene size and device conditions before advertising scale.
- **Simulation invariants** — No negative inventory, double-filled jobs or disconnected successful trips. Reconcile inventory changes with production, imports, exports, consumption and in-flight loads. Reconcile every ledger transfer. Replaying the same command stream at different render rates produces the same city state.
- **Balance gate** — Compare industrial-first, commuter-focused and higher-density openings. A viable city can grow, overbuilding can cause deficits, and the UI explains the available actions for recovery. Test that tax rates change household or firm behavior alongside the treasury.

**First branch deliverable:** a road-editing and rendering spike on an original sloping river map, with a working simulation worker, original-save isolation and comparable WebGL/WebGPU benchmark results. Use its measurements to lock the renderer and regional scope before replacing the live game entry point.
